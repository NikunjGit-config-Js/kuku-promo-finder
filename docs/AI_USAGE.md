# How AI tools were used, and where they got it wrong

**Tools.** Claude (Opus 5.5, claude.ai agent mode) helped survey the 50 scripts, write and debug the code and tests, run the evaluations, and draft docs. Claude's Research feature produced a market brief, and separate fact-checking agents verified its key claims against original sources. Web search was used for the Gemini free-tier limits and pricing. The LLM judge inside the tool is Gemini 2.5 Flash (free tier) by default and can be swapped via `--provider`.
ChatGPT helped troubleshoot the live Gemini API integration, explain test results, and plan the GitHub/Streamlit demo. A live Gemini `gemini-3.5-flash-lite` test on the synthetic two-episode show completed 2 calls with 0 failures and 1 selected promo; the confidential 50-episode run stayed offline. The exposed earlier API credential was not committed to this repository.

Every item below was observed in a real run. Script quotes are left out because this repo is public; the raw outputs, shared privately with Kuku, have them. The earlier outputs are kept in `raw_outputs/iterations/` as evidence.

| # | What went wrong | How it was caught | Fix |
|---|---|---|---|
| 1 | **AI-written parser bug.** A file with no episode number was numbered by file order. `Episode_two.txt` sorts before `ep-01.txt`, so it became Episode 1 and collided with a real "Episode 1". | Unseen-input test on the synthetic show. The validator flagged 2 invalid promos instead of writing wrong timestamps. | Unnumbered or duplicate episodes get the next free number and are reported. Regression test added. |
| 2 | **AI-designed lexicon over-scored a sound.** In v1, a bare "[SFX] A sharp, stunned gasp" scored 0.95 as the hook of Ep 26's best promo. | Reading the top picks. | Mood sounds (gasp, swell, sting) were moved to a lower tier. Ep 26 now opens on a spoken poisoning accusation. |
| 3 | **Rhetorical question scored as a perfect cliffhanger.** In v1, a 56 s, mostly one-speaker argument (Ep 32) ranked #2 with cliffhanger 1.0 for a rhetorical retort. | Reading the top picks. | A monologue penalty dropped it out of the top 10. Telling rhetorical questions from real ones is left to the LLM judge, because word rules can't do it. |
| 4 | **Hook was a reply to an unheard line.** In v1, the Ep 3 promo opened on a two-word reply. | Reading the top picks. | Short-line hook factor plus a penalty when the clip opens on a reply. |
| 5 | **Weighted average let a hookless clip through.** v3 recommended a quiet scene (Ep 17) because a decent ending compensated for a missing hook. | Auditing the lowest-ranked accepted promo. | Per-criterion floors (hook, cliffhanger, context). 15 weak promos dropped and the top 10 was unchanged. |
| 6 | **Still open: conflict-biased lexicon.** It recommends nothing for Ep 10, a strong romance-tension scene. | Checking episodes with zero promos. | Not patched by hand, which would mean tuning to the test set. This is the LLM judge's job (stakes and angle). |
| 7 | **AI-written validator crashed on malformed-but-valid JSON.** A reply of `{"candidates":[null]}` raised an unhandled error. A follow-up probe found five more failures: scalar items, dict/list IDs and an infinite score crashed the run; a score of 9 was silently clamped to 5, `true` was read as 1, and a duplicate ID overwrote the first answer. | Independent audit, then a targeted probe. | Strict type checks; out-of-range values are rejected, not clamped; duplicates keep the first answer; a reply with nothing usable triggers a retry, then the heuristic fallback. 30+ regression tests, including a local fake HTTP server. |
| 8 | **The AI research brief overstated or misquoted sources.** "Ads should pay off inside the free episodes" had no support (the sources suggest the payoff sits behind the paywall). "Kuku TV is ad-free" is out of date. "70–80% of content is AI" was said about *work*, not content. One title was misranked. | Three independent verification passes against original sources. | The early-episode launch window became a configurable editorial assumption instead of a research-backed rule. Only verified, dated facts go in the PDF. |
| 9 | **My own rescaling caused a silent regression.** After the cliffhanger score was rebalanced, the old floor became much stricter: coverage fell from 47 to 42 episodes and the synthetic show lost both Episode 1 promos. | Same-input before/after comparison. | Floors re-anchored at about the 30th–35th percentile of top candidates on the new scale, using no quality labels. Coverage is now 48/50. |
| 10 | **Still open: the quality list over-rates loud, context-heavy late scenes,** e.g. a late-season legal argument. | Editorial audit of the top 10. | Kept out of the launch batch by the spoiler tier. Rating these properly is the LLM judge's job; not fixed with word rules. |
| 11 | **A metric contradicted a recommendation.** The report said the first batch had no openings that reply to an unheard line, but one launch clip opened on a four-word reaction question followed by more words. The detector measured the length of the whole line instead of the first clause the viewer hears. It also matched answer words as prefixes, so "no" matched "nothing". | Spotted in the editorial audit, then flagged by the user. | The detector now reads the first clause (a lone name such as "Ethan?" is skipped) and matches whole words. Two regression tests added. The old batch now shows 1 reply opening and the new batch 0, because that clip now starts on its setup line. |

| 12 | **Untested compatibility claim.** The README promised Python 3.10+, but every run had used 3.13. One f-string that is only legal from Python 3.12 made the tool fail to import on 3.10 and 3.11. | Final release gate: compiled and ran the suite on Python 3.10 to 3.14. | Line rewritten; a test now rejects 3.12-only f-strings. All tests pass on Python 3.10 to 3.14. On 3.10/3.11 one score differs in the 4th decimal (Python 3.12 changed float `sum`); the recommendations are identical. |
| 13 | **Windows encoding assumptions.** JSON outputs used the operating system's default encoding: on a typical Windows PC they were not UTF-8, and a script line containing "₹" or Hindi text crashed the run at the very end. The review scorer silently skipped every row of a sheet saved by Excel as "CSV UTF-8" and crashed on Excel's ANSI CSV. | Emulating a Windows cp1252 system and Excel's two CSV formats before handing over the Windows instructions. | All files are read and written as UTF-8; the scorer accepts both Excel formats and treats a blank "would post" as unanswered. Regression tests run the whole command sequence under a non-UTF-8 system encoding. |
| 14 | **Two silent false successes.** The ±0.05 s timestamp tolerance was also applied to the 20–60 s rule, so a 19.95 s clip could pass validation (one such candidate existed in the pack; none was selected). Pointing `--input` at the screenplay .zip, which is stored uncompressed, parsed all 50 scripts as one "episode" and printed validated-looking promos with exit code 0. | An independent checker that re-reads the raw scripts without the tool's code, and reproducing common user mistakes. | Exact 20–60 s bounds; a .zip, a missing path or a folder without .txt files now stops with an error and exit code 2. Regression tests added. Promo picks unchanged. |
